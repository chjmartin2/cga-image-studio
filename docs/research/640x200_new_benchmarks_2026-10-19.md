# 640x200x1024 NEW: measured results, October 19, 2026

**Superseded GPU results.** This report preserves the first implementation's
measurements without dithering. Subsequent GUI verification exposed a CUDA
memory-layout bug in candidate rescoring; those GPU results do not establish
the current implementation's output, timing, or convergence guarantee. Legacy
results are unaffected. See [the corrected diffusion validation](640x200_new_dither_validation_2026-10-19.md)
for the fixed implementation and matching error-diffusion comparisons.

On the tested NVIDIA GeForce RTX 3090, NEW converted Raiders in **22.38 seconds**,
versus **162.82 seconds** for the legacy K=64 / 5% polish configuration. Its
sum of squared Lab errors was **36.88% lower**. Picard completed in **14.12
seconds**, and an actual GUI gradient conversion completed in **19.08 seconds**.
These are individual measurements, not guarantees for other images or hardware.

The stronger Raiders K=64 / 5% polish baseline took 7.27 times as long as NEW;
NEW used 86.25% less time. Relative to K=8 / no polish, NEW reduced
the squared-error objective by 62.65% on Raiders and 50.73% on Picard. The fast
K=8 Raiders baseline finished sooner than NEW; it also had substantially higher
measured error. There is no Picard K=64 / 5% polish measurement in this report.

The percentages refer specifically to **sum of squared Euclidean CIE Lab
distances**, also called squared Delta E76, across 128,000 pixels. They are
neither percentages of subjective visual improvement nor distances from a
proven global optimum. RMS Delta E76 is the square root of the mean squared
distance, and is a different quantity from the squared-error percentage.

## Inputs, settings and timing boundaries

Both image comparisons use the Old CGA simulator, a 640x200 target stretched
with Lanczos resampling, no dithering, no chroma low-pass filtering, and legacy
shape weight 1.0. The legacy settings remain explicitly recorded because its
search and polish controls differ from NEW's search domains.

Both outputs are decoded through the same complete-scanline reference decoder
and scored against the same prepared target. RGB-to-Lab values are float32;
differences and summed squared error use float64. **Neither output is reduced
to RGB444 for comparison.** Raw PNGs preserve complete decoder RGB. Comparison
images use nearest-neighbor 640x480 display scaling for CRT aspect ratio.

Encoding wall times include any lazy initialization and JIT compilation
incurred during the call. Rendering, file writing and comparison-image
generation are excluded. NEW ran first in the two paired reports; the second
encoder may reuse candidate caches. Existing on-disk compilation caches were
not purged, so these are not controlled cold-start experiments. The GUI smoke
timing below is a different boundary: conversion dispatch through completed
GUI processing, with export checks performed afterward.

The reports record Windows 11 build 26300, 32 logical CPUs, Python 3.12.0,
NumPy 2.4.6, Pillow 12.2.0, Numba 0.68.0 and CuPy CUDA 12.x package 14.2.0. NEW
used the RTX 3090 CUDA backend, with 82 GPU multiprocessors reported. That
GPU field is not a count of CPU worker threads. No runtime CPU fallback occurred
in these measured conversions. Full-image CPU fallback timing was not measured.

NEW considered all 23,536 distinct legal two-scanline RGBI cell patterns during
conditional scans. The final domain width was 64, with two alternate-context
proposal passes before final convergence. Raiders completed 26 passes and
Picard 25. Both reported convergence to a single-cell local optimum within the
1e-7 acceptance tolerance, and both explicitly reported
`global_optimum_certified: false`. Neither conversion ended because a time
budget expired.

## GUI, export and cancellation checks

An actual GUI gradient conversion completed in 19.07998 seconds; its internal
optimizer reported 18.62076 seconds and 11 passes. The preview exactly matched
the full-RGB decoder output. The exported COM contained the chosen cell data;
assembling the exported assembly reproduced the COM byte for byte; the COM
inside the disk image matched too. The COM and rebuilt COM share SHA-256
`8d146ceb3be2e08563ef2235ab5f9a3ef2069dfbfb4baa3f58184254a5f76968`.
See the [GUI/export report](../../artifacts/text-new-gui-smoke/gradient/report.json).

The [cancellation smoke report](../../artifacts/text-new-gui-smoke/cancellation-report.json)
records STOP, mode change, preset change and source change. All four cancelled
the in-flight conversion and blocked stale export. Observed cancellation
latencies were 0.066, 0.097, 0.910 and 1.051 seconds, respectively. These are
observations of those four runs, not latency guarantees.

## Automated validation and remaining limits

The full `pytest tests -q` run reported **83 passed, 174 subtests and 2 failed
in 69.86 seconds**. The two failures occurred in existing export-validity test
setup, while `_tkinter.create` was initializing Tk, before application
construction: missing/unreadable `vistaTheme.tcl` and invalid `tcl_findLibrary`.
The affected tests were:

- `ExportValidityTests::test_old_text_worker_cannot_replace_new_conversion`
- `ExportValidityTests::test_preview_and_export_only_controls_remain_valid`

Each passed when run in a fresh isolated process, in 0.66 and 0.57 seconds.
Repeating their whole test file produced three passes and another Tk
initialization failure. This is documented as a process/runtime isolation
limitation; the unrelated Tcl runtime issue was not fixed, and the full suite
is not claimed to be green.

A separate run of six NEW-specific test files reported **26 passed, 57
subtests and one Tk initialization error**. The affected
`NewTextIntegrationTests::test_queue_completion_preserves_diagnostics_and_exports_same_cells`
could not initialize Tk because `ttk/scrollbar.tcl` was unavailable; it passed
in a fresh isolated process in 0.50 seconds. The separate benchmark test passed
as well. Completed numerical and behavioral tests passed, including tiny
exhaustive decoder comparisons, true-context scoring, cached-domain checks,
CPU/CUDA agreement, parallel NumPy fallback, cancellation and export integration.
These isolated successes do not make either aggregate run an all-green result.

During test-harness investigation, a capture-disabled NEW-only run (`pytest
-q -s`) passed **28 tests and 57 subtests**. All five NEW GUI test cases also
passed on their first attempt in fresh processes, without retries or skips.
The final non-GUI NEW run passed 22 tests and 57 subtests. Explicit garbage
collection did not reliably resolve the initialization problem, and those
experimental test changes were reverted. Capture interaction remains an
unproven lead; neither the application nor its tests mask initialization
failures. See the [test-isolation record](../../artifacts/text-new-gui-smoke/tk-test-investigation.json).

The tested images met the under-one-minute goal on this GPU. Additional image
classes, repeated timing distributions, other GPUs, and full-image CPU runs
remain useful follow-up measurements. The implemented search is exact over
each proposed fusion domain and preserves accepted objective improvements;
it does not prove that the final image is globally best over every possible
character/attribute combination. See the
[algorithm research and guarantees](640x200_new_search_research.md).
